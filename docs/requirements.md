# Первая версия

## Сценарий

1. Пользователь загружает видео.
2. Сервис извлекает аудио и получает расшифровку с временными метками.
3. Модель предлагает до трёх законченных фрагментов: название, объяснение выбора, начало и конец.
4. Сервис создаёт видеофайлы с субтитрами.
5. Пользователь просматривает и скачивает результат, при необходимости меняет границы и повторяет экспорт.

## Медиа

- Вход: MP4, до 300 МБ и 30 минут. Лимиты задаются в конфигурации.
- Одна основная речевая дорожка.
- До трёх фрагментов продолжительностью 15–60 секунд.
- Один стиль субтитров с поддержкой русского языка.
- Выход: MP4, воспроизводимый в браузере.
- Формат 9:16: исходное изображение вписано в фон без обрезки содержимого кадра.

## Архитектура

- Backend на Go: модульный монолит с фоновыми воркерами.
- Frontend на React и TypeScript.
- PostgreSQL хранит задания, состояние этапов, расшифровки и результаты.
- Локальное файловое хранилище доступно через отдельный интерфейс.
- FFmpeg и ffprobe выполняют анализ и обработку медиа.
- Локальный запуск через Docker Compose.
- Стабильные версии зависимостей; внешние API интегрируются по официальной документации.

## Обработка заданий

- Потоковая загрузка без чтения всего видео в память.
- HTTP-запрос создания задания не ждёт завершения обработки.
- Безопасное получение заданий несколькими воркерами с ограничением параллелизма.
- Таймауты и отмена через context, корректное завершение приложения.
- Восстановление незавершённых заданий после перезапуска, в том числе при падении воркера во время обработки.
- Ограниченные повторы временно неудавшегося этапа с использованием сохранённых результатов завершённых этапов.
- Очистка временных файлов и структурированные логи с идентификатором задания.
- FFmpeg запускается с отдельными аргументами, контролем завершения, ограниченным сбором stderr и отменой.
- Гарантии доставки и повторного выполнения описываются по фактической реализации; exactly-once не предполагается.

## Распознавание и выбор фрагментов

Распознавание речи и выбор фрагментов имеют отдельные заменяемые интерфейсы. Для каждого нужен один реальный провайдер. Ключи передаются через переменные окружения.

Ответ модели содержит начало, конец, название и объяснение выбора. Go-код проверяет границы видео, порядок временных меток, длительность, дубликаты и чрезмерные пересечения. Субтитры должны соответствовать выбранному интервалу.

Для проверки без API-ключей нужен отдельный режим с готовой расшифровкой, явно обозначенный в интерфейсе. Он проверяет обработку реального видео и не заменяет проверку внешней AI-интеграции.

## Интерфейс

- Загрузка перетаскиванием и история заданий.
- Страница задания с текущим этапом, ошибками и повторным запуском.
- Расшифровка с временными метками и карточки предложенных фрагментов.
- Видеоплеер, скачивание, изменение границ и повторный экспорт.
- Название этапа и индикатор ожидания, если точный процент выполнения неизвестен.

## Проверка

- Недопустимый файл и превышение лимита.
- Некорректные временные метки от модели.
- Ошибка внешнего API и ошибка FFmpeg.
- Отмена обработки и перезапуск воркера.
- Конкурентное получение заданий.
- Smoke-тест на небольшом видео: выходной файл создан, имеет ожидаемую длительность и читается через ffprobe.

## Критерии готовности

Основной сценарий работает от загрузки до скачивания реальных клипов и повторного экспорта. Проверки запущены, найденные ошибки исправлены. Дополнительные функции — после проверки первой версии.

Репозиторий содержит миграции, `.env.example` без секретов, команды запуска и тестирования, документацию основных API и воспроизводимый демонстрационный сценарий. Документация описывает архитектурные решения, ограничения, результаты проверок и настройку внешних провайдеров.
