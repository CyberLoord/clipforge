# Устройство

Один Go-процесс обслуживает HTTP и запускает пул воркеров. React собирается в статические файлы и раздаётся тем же сервером. PostgreSQL хранит задания; исходники и результаты лежат в отдельном каталоге данных.

## Этапы

`probe → transcribe → select → render → completed`

После этапа воркер сохраняет результат и следующий этап в PostgreSQL. Повтор после ошибки использует уже сохранённые данные. Для повторного экспорта меняются границы и ревизия одного клипа, очищается его ссылка на файл; остальные клипы остаются доступными.

Загрузка потоковая. Сначала проверяются расширение, сигнатура контейнера и размер, затем файл атомарно переименовывается и создаётся задание. ffprobe асинхронно проверяет дорожки, длительность и разрешение. HTTP-запрос не ждёт обработки видео.

## Очередь

Получение задания выполняется одним SQL-запросом с `FOR UPDATE SKIP LOCKED`. Каждая попытка получает случайный токен и срок аренды. Heartbeat продлевает аренду; все записи результата проверяют токен, статус и срок. Потеря аренды отменяет текущий context.

После сбоя другой воркер подбирает просроченное задание. Этап может выполниться повторно, включая платный запрос к провайдеру. Гарантии exactly-once нет. Уникальные пути файлов и проверка токена не позволяют старой попытке подменить опубликованный результат.

Временные сетевые ошибки, 429, 5xx и таймауты повторяются с задержкой и ограничением попыток. Ошибки входных данных, невалидные ответы модели и ошибки FFmpeg завершают задание. Пользователь может запустить повтор вручную. Отмена фиксируется сразу, процесс останавливается при следующем heartbeat, по умолчанию не позднее примерно 10 секунд при доступной БД.

При SIGTERM сервер завершает HTTP-запросы и отменяет воркеры. Незаконченные задания остаются для восстановления после истечения аренды. Попытки, оборванные аварийно, также учитываются в лимите.

## Медиа и AI

FFmpeg запускается через `exec.CommandContext` с отдельными аргументами. Вход ограничен локальными MP4, stderr ограничен 8 КиБ. Выход: H.264, yuv420p, AAC, faststart, 540×960. Исходное изображение вписывается в тёмный фон. В контейнере установлены libass и DejaVu Sans для русских субтитров.

Аудио извлекается в mono MP3, 16 кГц, 32 кбит/с. Распознавание и выбор фрагментов имеют разные интерфейсы. OpenAI возвращает сегменты с временными метками и структурированный список клипов; Go проверяет границы, длительность, число фрагментов и пересечения более половины меньшего интервала.

Распознавание использует сегментные временные метки. Для длинного сегмента время между группами слов распределяется приблизительно; покадровой синхронизации каждого слова нет. Группы субтитров обрезаются по интервалу клипа.

Документация провайдера: [speech-to-text](https://developers.openai.com/api/docs/guides/speech-to-text), [structured outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=chat).

## Ограничения

- Один пользователь, без авторизации. Compose публикует порт только на `127.0.0.1`; для общего доступа нужны аутентификация и ограничения запросов.
- Локальная файловая система. Несколько процессов должны видеть один каталог данных; `WORKERS` ограничивает параллелизм каждого процесса.
- История показывает последние 100 заданий. Политики удаления исходников и завершённых заданий пока нет. Нужно следить за свободным местом. При потере ответа на INSERT исходник сохраняется: неизвестный результат записи в БД не должен оставить возможное задание без видео; такой сбой может оставить лишний исходник.
- Одна основная аудиодорожка, без отслеживания лица и умного кадрирования. Видео короче 20 секунд, длиннее настроенного лимита или с разрешением выше 8K не принимается.
- Выбор содержательных фрагментов зависит от модели. В деморежиме нет распознавания или смыслового анализа.
- Клиент OpenAI проверяется на тестовом HTTP-сервере. Реальные запросы требуют пользовательского ключа и отдельной проверки качества на своей речи.
